# 🤖 بوت إدارة حسابات تيليجرام

بوت تيليجرام احترافي لإضافة وإدارة حسابات تيليجرام متعددة بأمان كامل.

---

## ✨ الميزات

- ➕ إضافة حسابات عبر رقم الهاتف (OTP)
- 🔐 دعم التحقق بخطوتين (2FA)
- 🔒 تشفير الجلسات (AES-256)
- 📋 عرض قائمة الحسابات مع حالتها
- 🔄 إعادة تسجيل الدخول لأي حساب
- 📊 فحص حالة الاتصال لحظيًا
- 🗑️ حذف الحسابات مع تنظيف الجلسات
- 🛡️ معالجة كاملة لأخطاء تيليجرام API
- 💳 زر تفاعلي لعرض الاشتراك وتفعيل الأكواد
- 🎟 أكواد اشتراك بمدد 30/60/90 يومًا أو Lifetime
- 🔢 حد حسابات مستقل لكل كود مع منع التجاوز
- 🛠 لوحة أدمن لتوليد كود واحد أو دفعة أكواد وإحصائيات الاشتراكات
- 📅 جدولة نشر دائمة محفوظة في قاعدة البيانات
- 🔁 جدولات مرة واحدة أو يومية أو أسبوعية أو مخصصة
- 🧾 ملخصات وجدولات قادمة وسجل نجاح/فشل لكل عملية
- 🛡️ منع تضارب الجدولات وعزل أخطاء كل مهمة

## 🚀 التثبيت

### 1. المتطلبات

- Node.js 18+
- حساب تيليجرام مطور: https://my.telegram.org

### 2. إعداد المشروع

```bash
# نسخ المشروع
git clone <repository-url>
cd telegram-account-bot

# تثبيت المكتبات
npm install

# إعداد متغيرات البيئة
cp .env.example .env
```

### 3. إعداد ملف .env

```env
BOT_TOKEN=        # من @BotFather
API_ID=           # من https://my.telegram.org
API_HASH=         # من https://my.telegram.org
ENCRYPTION_KEY=   # مفتاح عشوائي 32+ حرف
ADMIN_IDS=         # معرفات Telegram الرقمية للأدمن، مفصولة بفواصل
OWNER_ID=          # معرف مالك واحد اختياري، وله صلاحيات الأدمن نفسها
BOT_OWNER_ID=      # اسم بديل اختياري لـ OWNER_ID
DATABASE_URL=       # رابط PostgreSQL من Variables في منصة الاستضافة
DATABASE_SSL=true
```

### 4. الحصول على API_ID و API_HASH

1. افتح https://my.telegram.org
2. سجّل دخول برقم هاتفك
3. اضغط "API development tools"
4. أنشئ تطبيقًا جديدًا
5. انسخ `api_id` و `api_hash`

### 5. تشغيل البوت

بعد التشغيل ستظهر في القائمة الرئيسية أزرار **💳 الاشتراكات** و**🎟 تفعيل كود الاشتراك**.

### جدولة النشر

من **📅 جدولة النشر** يمكن إنشاء جدولة عبر اختيار حساب أو عدة حسابات، وجهة أو عدة وجهات، إعلانًا من المكتبة أو منشورًا جديدًا، ثم تحديد الموعد والتكرار والتأخير. تتوفر إدارة الجدولات الحالية، المنشورات القادمة، التشغيل والإيقاف، التعديل، الحذف، التفاصيل، الإحصائيات، وسجل العمليات.

تُحفظ الجدولات في قاعدة البيانات وتستعيد عملها بعد إعادة تشغيل البوت. يستخدم المحرك قفلًا لكل جدولة لمنع التنفيذ المتوازي، ويتحقق من التضارب، ويسجل نجاح أو فشل كل حساب ووجهة دون إيقاف الجدولات الأخرى. اختبار التدفق المحلي:

```bash
npm run test:schedule
```

### نقل قاعدة SQLite إلى PostgreSQL

يجب تنفيذ النقل مرة واحدة على بيئة تحتوي على ملف SQLite القديم ومتغير `DATABASE_URL`، مع إبقاء مجلد `sessions/` محفوظًا لأنه يحتوي على ملفات جلسات تيليجرام المشفرة:

```bash
SQLITE_PATH=./data/accounts.db DATABASE_URL="$DATABASE_URL" pnpm run migrate:postgres
```

السكربت ينشئ الجداول الناقصة وينقل السجلات دون حذف بيانات موجودة في PostgreSQL، ويمكن إعادة تشغيله بأمان. بعد نجاح النقل، تحقّق من عدد الحسابات والاشتراكات قبل تحويل تشغيل البوت إلى طبقة PostgreSQL.

يُفعّل الأدمن لوحة الإدارة ويُعفى من شرط الاشتراك بإضافة معرفه الرقمي في `ADMIN_IDS`. ويمكن بدلاً من ذلك وضع معرف المالك الواحد في `OWNER_ID` أو `BOT_OWNER_ID`. يجب أن يكون المعرف رقم Telegram الرقمي، وليس اسم المستخدم أو رقم الهاتف. عند وجود `DATABASE_URL` يستخدم البوت PostgreSQL تلقائياً وتُنشأ الجداول عبر الترحيلات؛ أما SQLite فيبقى fallback للتشغيل المحلي عند غياب المتغير.

عند محاولة إضافة حساب، يُفحص الاشتراك والمدة من قاعدة البيانات قبل إنشاء جلسة OTP للمستخدمين العاديين، بينما يتجاوز المالك أو الأدمن المسجل هذا الفحص. لذلك بعد تحديث متغير البيئة وإعادة تشغيل البوت سيظهر له أيضاً زر **لوحة الأدمن** ولن يُطلب منه كود اشتراك لإضافة الحسابات.


```bash
# للإنتاج
npm start

# للتطوير
npm run dev
```

## 🔒 الأمان

- جميع الجلسات مشفرة بـ AES-256
- كلمات المرور تُحذف فورًا من المحادثة
- لا تُخزَّن بيانات الاعتماد في الكود
- المتغيرات الحساسة في ملف `.env` فقط
- التحقق من جميع المدخلات قبل المعالجة
